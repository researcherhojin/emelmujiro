# Backend rules

## Architecture

Invariants only. Grep the code for everything else. Single app `api/`; `config/` holds settings and the root URLconf.

- **The view layer is split four ways, not one `views.py`**: `views.py` (public API — blog, comments, image upload, categories, contact, newsletter, notifications, `health_check`, the `DEBUG`-only `send_test_email` (routed only under `if settings.DEBUG` in `api/urls.py`), plus 3 of the 5 throttle classes), `admin_views.py` (8 admin endpoints and `AdminRateThrottle`, so it imports nothing from `views.py`), `auth.py` (`login` / `logout` / `get_user` / `update_user` / `change_password` / `token_refresh` + the `_set_jwt_cookies` / `_clear_jwt_cookies` helpers), and `authentication.py` (`CookieJWTAuthentication`). New endpoints go in the module matching their audience — do not grow `views.py` into an admin or auth home.
- **Auth is cookie-first, header-fallback**: `CookieJWTAuthentication` reads `settings.JWT_ACCESS_COOKIE` (`"access_token"`, refresh is `"refresh_token"`) and only falls back to the `Authorization` header when the cookie is absent or invalid. Tests and API clients can use either; the browser always uses the cookie. Never move token issuance out of `auth.py`'s cookie helpers — that's the one place `httpOnly`/`SameSite` flags are set. Cookie-authenticated writes use Django CSRF checks; login and refresh always require CSRF because both issue cookies. Logout skips access-token authentication but always requires CSRF, revokes the refresh cookie before any body token, and clears cookies even when access has expired. `auth/csrf/` returns a non-cacheable masked token with an httpOnly cookie, including when access cookies have expired. `CHECK_REVOKE_TOKEN` rejects tokens without the current password claim; the custom refresh view must check that claim and `is_active` before rotation.
- **Middleware position is load-bearing** (`config/settings.py` `MIDDLEWARE`): `RequestSecurityMiddleware` runs **before** Session/CSRF/Authentication so it can reject malicious patterns and blocked IPs without a DB session; `ContentSecurityMiddleware` and `APIResponseTimeMiddleware` run **last** so they see the final response. Reordering these silently changes what they can inspect.
- **`APIResponseTimeMiddleware` writes the API access log — the only request-level record of `api.emelmujiro.com` traffic.** gunicorn has no `--access-logfile` (`backend/Dockerfile`), `debug.log`/`security.log` sit at `WARNING` in production, container logs are discarded on every deploy, and the frontend nginx never sees API calls because the production build calls the API host directly (root `CLAUDE.md` Gotchas #7, #18). It logs method, full path, status, duration, IP (from `api/utils.get_client_ip`, never a client-settable header), **referer and user-agent** — the last two separate first-party calls from external consumers. `/api/health/` (Docker probes it every 30 s) and non-`/api/` paths are skipped. The `api.access` logger is **file-only with `propagate: False`**, uses a `RotatingFileHandler` (5 MB, `backupCount: 3`, ~20 MB across 4 files), and is in the `TESTING` NullHandler list so tests cannot write the production file. **Adding a field changes what is retained about visitors** — the privacy policy's `[자동 수집 항목]` covers the current set.
- **Never `cache.incr()` (or its decrement twin) on the production cache.** It is `FileBasedCache`, which inherits `BaseCache.incr()`: a `get` then a `set` with **no timeout**, i.e. the default `TIMEOUT` of 300 s, so every increment silently shortens the key's lifetime to 5 minutes. Django's docs do not say whether `incr()` keeps the expiry; they do say it is a non-atomic two-step retrieve/update on backends without native increment. `RequestSecurityMiddleware.is_rate_limited` therefore stores `(window_start, count)` under the unchanged `rate_limit_{ip}` key (`rate_limit_key()` in `api/constants.py`) — the key name is load-bearing because `security_check --action=unblock` deletes it — and writes it with the explicit remaining lifetime. **Test caching behavior on `FileBasedCache`, not `LocMemCache`**: LocMem overrides `incr()` and keeps the expiry, which is how `RequestSecurityMiddlewareTestCase` hid this; `RateLimitWindowTestCase` runs on the production backend with a fake clock.
- **`RequestSecurityMiddleware` inspects every value of a repeated query key** (`QueryDict.lists()`). `QueryDict.items()` and `.values()` yield only the last value per key, so `?q=<payload>&q=ok` passed the check (d25bad1f). Ruff's PERF102 suggests `.values()` on that loop — do not take it.
- **`api/urls.py` ordering is a collision guard**: `blog-posts/upload-image/` and the nested `blog-posts/<post_pk>/comments/…` paths are registered **before** `include(router.urls)`, because the `DefaultRouter` detail route `blog-posts/{id}/` would otherwise swallow them. Add new `blog-posts/…` sub-paths above the `include`, never below. Router basenames: `blog` (not `blogpost`) and `notification`.
- **The public blog-list cache is one fixed key (`CACHE_BLOG_POST_LIST`), so it serves only a request with no query string at all.** An allow-list of filters once missed `page_size`, so a cold-cache `?page_size=1` served a 1-item list to every bare request for 30 s (ff296fb4). Any new fixed-key response cache needs the same any-parameter bypass, not a filter list.
- **A blog translation is tied to the Korean text it was made from.** `BlogPost.translation_source_hash` is stamped (`mark_translation_current()`) whenever an English field is written — `BlogPostWriteSerializer` on any `_en` key, `BlogPostAdmin.save_model` on a changed `_en` field, or the admin action `confirm_translation_current` — and `is_translated` requires it to equal `korean_source_hash(title, description, content_html)`. Writing English fields any other way (a shell script, `.update()`) must call `mark_translation_current()` too, or the post reads as untranslated. Migration `0014` holds a frozen copy of the hash function; a test asserts they agree, so change both or neither.
- **10 models** in `api/models.py`: `BlogPost`, `BlogLike`, `BlogComment`, `CommentLike`, `Contact`, `ContactAttempt`, `SiteVisit`, `Notification`, `NotificationPreference`, `NewsletterSubscription`.
- **Throttles use `api/throttling.py` to share `get_client_ip()` with the middleware; never use raw forwarded headers for bucket keys.**
- **Throttle rates are declared in two places and the inline `rate` wins.** `REST_FRAMEWORK.DEFAULT_THROTTLE_RATES` holds `anon` 100/h, `user` 1000/h, `login` 10/h, `contact` 5/h, `newsletter` 3/h, `admin` 120/h — but `ContactRateThrottle`, `CommentRateThrottle` (`views.py`) and `AdminRateThrottle` (`admin_views.py`) each set an inline `rate`, which overrides the settings entry, so editing settings alone changes nothing for those three. `comment` has no settings entry at all; its 10/h lives only on the class. `LoginRateThrottle` (`login_throttle.py`) and `NewsletterRateThrottle` (`views.py`) deliberately omit `rate` so settings is their single source of truth — **prefer that shape for new throttles.** `health_check` is exempt on purpose (`@throttle_classes([])`) because Docker probes it every 30s.
- **A scope only exists if a throttle class declares it.** `newsletter: 3/hour` was dead config (694367ce): `NewsletterView` used a bare `AnonRateThrottle`, whose scope is `anon`, so signups silently got the 100/h anon bucket. Adding a rate to `DEFAULT_THROTTLE_RATES` does nothing on its own. Two traps this left behind, both still live: `@override_settings(REST_FRAMEWORK={...DEFAULT_THROTTLE_RATES...})` in tests **does not disable a throttle** — DRF binds `SimpleRateThrottle.THROTTLE_RATES` as a class attribute at import, so the override never reaches it; the two test classes that pass `"newsletter": None` are decorative. The pattern that actually works here is `cache.clear()` in `setUp` (see `ContactAPITestCase`, `NewsletterAPITestCase`) — a throttled endpoint's tests share the counter across the class otherwise. Local dev (`DEBUG=True`) runs without throttling — see root `CLAUDE.md` → `Constraints` → Local dev vs Docker.

## Constants

`api/constants.py` centralizes `ONE_HOUR`, `ONE_DAY`, `SPAM_KEYWORDS`, `SPAM_THRESHOLD`, `MAX_FAILED_CONTACT_ATTEMPTS`, `is_spam()`, cache keys (`CACHE_BLOG_CATEGORIES`, `CACHE_BLOG_POST_LIST`, `CACHE_ADMIN_STATS`), and the per-IP key builders `temp_block_key()`, `rate_limit_key()`, `block_count_key()` that `RequestSecurityMiddleware` writes and `security_check --action=unblock` deletes (`SecurityCacheKeyTestCase` pins the strings). Import from here — do NOT re-define time constants or cache keys in views, middleware or management commands. Page-size limits come from `api/pagination.py` `StandardPagination` (`max_page_size = 100`), which `admin_views.parse_pagination_params` also reads. `django-extensions` + `ipython` are dev-only (`uv sync --extra dev`).

## Utilities

`api/utils.py` has `get_client_ip()`, `_is_valid_ip()`, `toggle_like()`, `sanitize_referer()`. IP extraction is shared by views and middleware — import from utils, not views.

## Testing

**Backend test output is intentionally noisy** — `ERROR`/`WARNING` lines come from negative-path tests (XSS/SQL/path-traversal middleware, SMTP/DB failure paths, JWT invalid tokens, reCAPTCHA fallbacks, blocked IPs). Trust `Ran N tests OK` + exit code 0, not the absence of log lines.

**Tests keep the production `FileBasedCache`, in a `mkdtemp` directory** (`config/settings.py`, `Test environment overrides`, removed at exit), so a run never reads or writes the dev server's `backend/.cache`. Do not reintroduce a `DummyCache` default: `CategoryCacheTestCase` and `RateLimitWindowTestCase` need a real cache, and the early-block `DummyCache` that claimed to isolate tests never applied (overridden by the later `CACHES`, removed in #576).

## Tooling

**Inside the backend container, run Django through `/app/.venv/bin/python`**: the runtime image ships no uv since #705 (its bundled TLS crate kept the image scan red), and the venv is first on `PATH`. Callers use the absolute path anyway: the refresh rollback rehearsal and the host cron lines may hit an older image, where bare `python` is the system interpreter and fails with `No module named 'django'`. Use `docker exec -i emelmujiro-backend /app/.venv/bin/python manage.py shell < script.py` for one-off data scripts.

`black` + `flake8` (line length 120) are the only Python lint gates. `[tool.ruff]` in `pyproject.toml` exists so the VS Code Ruff extension agrees with them (line length, `py312`, `api`/`config` first-party). It is not run in CI, so its editor findings in `backend/` are not failures (d25bad1f).

**Re-lock with the image's uv, not the local one**: `backend/Dockerfile` copies uv `0.12.24` and builds with `uv sync --frozen`, while a newer local uv rewrote `uv.lock`'s `revision = 3` to `5` on a one-package `--upgrade-package` (030ddeb5); the committed lock is at `revision = 5` since #682 (`44bfb339`). Use `uvx uv@<Dockerfile version> lock --upgrade-package <pkg>` and confirm the diff touches only that package.

## Deployment

**The backend container runs `migrate --noinput` before gunicorn** (`backend/Dockerfile` `CMD`); nothing in `auto-deploy.sh` migrates; with a manual `make migrate`, endpoints on the changed table returned `500` while `/api/health/` stayed green (a98fbd34). A failed migration stops the container rather than serving a mismatched schema. Keep migrations additive (nullable or defaulted fields): the frontend build in the same deploy runs against the old backend.

## Security

- **Production keys**: a missing `SECRET_KEY` raises `ImproperlyConfigured` when `settings.py` loads; a missing `RECAPTCHA_PRIVATE_KEY` raises it inside `verify_recaptcha` (`api/views.py`) on the first contact submission, so the server starts and the first form post fails (DEBUG bypasses reCAPTCHA).
- **File uploads**: Backend uses `uuid4` filenames (no user-supplied paths). Validated against extension whitelist + MIME type + 5 MB limit.
- **Image endpoint**: `validate_uploaded_image()` additionally decodes JPEG, PNG and GIF; documents are rejected even when the generic upload settings permit them. Pillow's pixel ceiling is set once at module import, before decoder allocation, with decompression warnings treated as errors. Limits are 16,000,000 pixels per frame, 32,000,000 total pixels and 100 frames. Validate every animation frame and reset the stream before storage. Tests must use real encoded images, not headers followed by arbitrary bytes.
- **Runtime image**: the Python 3.12 Alpine base is shared by both Docker stages; never copy a glibc virtual environment into musl. Compiler tools and development headers stay in the Docker dependency stage. The runtime copies its virtual environment and uses uv; pip is removed from the base runtime. Verify changes with tests inside the built container, not just the host environment.

Authentication regression contract and deployment evidence: `docs/intents/backend/security-review-fixes.md`.

**Login throttling serializes FileBasedCache updates with a filesystem lock**
(`api/login_throttle.py`), shared by all workers and threads on the deployment
host. Lock acquisition times out after one second and fails closed. This is
single-host protection; cache eviction and restarts can still reset counters,
and it does not replace edge rate limiting or DDoS protection. Regression tests
exercise both processes and threads.
